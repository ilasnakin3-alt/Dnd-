# Практика 1. Проектирование будущего продукта[cite: 2]
## Сайт клуба настольных ролевых игр по Dungeons & Dragons[cite: 2]

### Постановка задачи[cite: 2]
За семестр команда из 4 человек должна разработать коммерчески применимый веб-сайт клуба настольных ролевых игр, организующего игровые сессии по Dungeons & Dragons[cite: 2].
Проект должен содержать полноценный frontend, backend, БД, административную часть, формы взаимодействия с клиентом, SEO, контейнеризацию и production-развёртывание[cite: 2].

---

### 1. Выбор предметной области[cite: 2]
Корпоративный сайт клуба настольных ролевых игр «Драконий Порог» в Челябинске с расписанием игровых сессий, каталогом мастеров, описаниями систем и кампаний, галереей отчётов с игр и формой записи на сессию[cite: 2].

**Почему эта тема:**
- DnD — растущее хобби в России, спрос на организованные игры высокий[cite: 2];
- Клубы в Челябинске существуют, но у большинства только группа ВКонтакте, полноценных сайтов почти нет[cite: 2];
- Тема допускает богатый контент: мастера, кампании, системы, статьи, отзывы — есть что класть в БД[cite: 2];
- Подходит под формат «сайт услуг / корпоративный сайт»[cite: 2].

---

### 2. Определение условного заказчика[cite: 2]
- **Основные услуги:** организация игровых сессий D&D 5e, кампании и ваншоты, мастер-классы для новичков, аренда игрового пространства, индивидуальные игры с мастером[cite: 2].
- **Дополнительно:** продажа дайсов и расходников на месте, партнёрство с магазином настольных игр[cite: 2].
- **Основная цель сайта:** получение заявок на запись в игровые сессии и привлечение новых игроков[cite: 2].

---

### 3. Определение целевой аудитории[cite: 2]

#### 1 — Кто заходит на сайт?[cite: 2]
Мужчина или женщина 18–45 лет, который хочет попробовать Dungeons & Dragons или найти постоянную группу в Челябинске[cite: 2]. Возможно, опытный игрок, переехавший из другого города[cite: 2]. Возможно — компания друзей, ищущая корпоративный тимбилдинг в необычном формате[cite: 2].

#### 2 — Что он хочет узнать?[cite: 2]
- какое расписание игр доступно на ближайшие недели[cite: 2];
- сколько стоит участие в сессии[cite: 2];
- какие мастера ведут игры и какой у них опыт[cite: 2];
- подойдёт ли игра для новичков[cite: 2];
- какие системы и сеттинги представлены[cite: 2];
- что нужно взять с собой на игру[cite: 2];
- отзывы других игроков[cite: 2];
- контакты и как добраться до клуба[cite: 2];
- можно ли записаться онлайн[cite: 2].

#### 3 — Что хочет владелец бизнеса?[cite: 2]
Получить контакт потенциального игрока, записать его на сессию и конвертировать в постоянного клиента (абонемент на кампанию)[cite: 2].

**Ключевая цепочка:**
Пользователь → Сайт → Расписание → Выбор сессии → Доверие (мастер, отзывы) → СТА «Записаться» → Заявка → Организатор клуба[cite: 2]

### 4. Анализ конкурентов[cite: 2]
Найдены 3 существующих сайта клубов НРИ в России[cite: 2]:

| Критерий | ДАНЖ (данж.рф) | Феникс (fenix-nri.ru) | Уютное подземелье (cozy-dungeon.ru) |
| :--- | :--- | :--- | :--- |
| **Расписание игр на сайте** | Нет (только в ВК) | Да, интерактивное | Да, календарь |
| **Каталог мастеров** | Да, с ценами | Да, с фото | Да |
| **Цены на услуги** | Да, подробные | Нет на сайте | Нет |
| **Онлайн-запись** | Через ВК | Через сайт | Через сайт |
| **Описание систем/сеттингов** | Кратко | Нет | Да, раздел «Во что поиграть?» |
| **Статьи/блог** | Нет | Нет | Нет |
| **Отзывы игроков** | Нет | Нет | Нет |
| **Мобильная версия** | Средняя | Хорошая | Хорошая |
| **Что понравилось** | Чёткие цены, поиск мастера | Расписание с записью | Структура, календарь |

**Вывод из анализа:**
У большинства клубов сайты решают базовую задачу — показать расписание и записать на игру[cite: 2]. Но почти нигде нет: отзывов, блога со статьями для новичков, цен, подробных карточек мастеров[cite: 2]. Это те зоны, где наш сайт может выделиться[cite: 2].

### 5. Формулирование основной бизнес-цели сайта[cite: 2]
**Основная бизнес-цель:** получение заявки на запись в игровую сессию (ваншот или кампанию) от потенциального игрока через форму на сайте[cite: 2].

### 6. Определение MVP[cite: 2]
Минимальная жизнеспособная версия сайта, которую уже не стыдно показать заказчику[cite: 2]:
- Главная (с описанием клуба, преимуществами, CTA)[cite: 2]
- Расписание игр (список сессий с фильтром по дате и системе)[cite: 2]
- Карточка сессии (описание, мастер, цена, дата, кнопка записи)[cite: 2]
- Мастеры (список)[cite: 2]
- Карточка мастера (фото, опыт, системы, отзывы)[cite: 2]
- О клубе (история, фото пространства, контакты)[cite: 2]
- Статьи (список)[cite: 2]
- Статья (отдельная страница)[cite: 2]
- Контакты (адрес, карта, форма обратной связи)[cite: 2]
- Форма записи на сессию (имя, телефон, сессия, комментарий)[cite: 2]
- Административная панель (управление сессиями, мастерами, статьями, заявками)[cite: 2]

### 8. Пользовательские сценарии[cite: 2]

#### Сценарий №1 — Запись новичка на ваншот[cite: 2]
1. Пользователь открывает главную страницу[cite: 2].
2. Видит блок «Что такое D&D?» и кнопку «Записаться на игру»[cite: 2].
3. Переходит в расписание игр[cite: 2].
4. Фильтрует по уровню «для новичков»[cite: 2].
5. Выбирает ваншот на ближайшую субботу[cite: 2].
6. Открывает карточку сессии: описание, имя мастера, цена, дата[cite: 2].
7. Нажимает «Записаться»[cite: 2].
8. Заполняет форму: имя, телефон, комментарий[cite: 2].
9. Получает сообщение об успешной отправке заявки[cite: 2].

#### Сценарий №2 — Опытный игрок ищет кампанию[cite: 2]
1. Пользователь открывает расписание игр[cite: 2].
2. Фильтрует по типу «Кампания» и системе «D&D 5e»[cite: 2].
3. Изучает карточки доступных кампаний[cite: 2].
4. Открывает карточку мастера, читает отзывы[cite: 2].
5. Возвращается к карточке сессии[cite: 2].
6. Нажимает «Записаться», заполняет форму[cite: 2].
7. Получает подтверждение[cite: 2].

#### Сценарий №3 — Администратор создаёт новую сессию[cite: 2]
1. Администратор открывает Django Admin[cite: 2].
2. Переходит в раздел «Сессии»[cite: 2].
3. Нажимает «Добавить сессию»[cite: 2].
4. Заполняет: название, описание, систему, мастера, дату, цену, количество мест, уровень для новичков[cite: 2].
5. Загружает изображение[cite: 2].
6. Заполняет SEO title и description[cite: 2].
7. Сохраняет и публикует[cite: 2].
8. Сессия появляется в расписании на сайте[cite: 2].

*Последний сценарий показывает: контент не должен находиться в HTML — сессии, мастера и статьи создаются через админ-панель и хранятся в БД[cite: 2].*

### 11. Основные требования к production-версии[cite: 2]
- Полноценный frontend на шаблонизаторе с адаптивной вёрсткой[cite: 2].
- Backend на Django с моделями: `Session`, `Master`, `System`, `Article`, `Gallery`, `Review`, `Application`[cite: 2].
- БД PostgreSQL с миграциями[cite: 2].
- Административная панель Django Admin для управления всем контентом[cite: 2].
- Формы: запись на сессию, обратная связь — с валидацией и сохранением в БД[cite: 2].
- SEO: динамические title и description для каждой страницы, `sitemap.xml`, `robots.txt`[cite: 2].
- Контейнеризация: Docker Compose (web, db, nginx)[cite: 2].
- Production-развёртывание на VPS с Gunicorn + Nginx, HTTPS через Let's Encrypt[cite: 2].
- Медиафайлы: загруженные изображения мастеров, сессий, галереи[cite: 2].
- Статика: CSS, JS, шрифты — собраны через `collectstatic`[cite: 2].
